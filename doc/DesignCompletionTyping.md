# 持续输入时刷新补全

2026-11-09，基于 SourceView `e536adc`、GOUI v0.7.0，补充 [补全设计](DesignCompletion.md)。
公开接口继续使用 CompletionProvider、RefreshCompletion 和既有补全字段。

## 行为

同一词范围、同一有效语言定义内的普通文本输入、Backspace 和 Delete 延续当前会话，
复用 Popover、ScrollView 和候选列表控件。按键与实际文本提交是两个事件；可打印键、
Shift 和 AltGr 不提前关闭弹窗，实际提交后才决定是否仍属于本词。
默认来源从新上下文重新计算；自定义来源仍完全负责过滤和排序。
手动打开的会话保留 Explicit，即使关闭 AutomaticCompletion 也可以继续刷新。
输入携带实际 Trigger，删除携带空 Trigger。

异步期间保留旧列表预览并标记 pending，禁止 Enter/Tab、点击、hover 和上下键提交或
改变旧候选。只保留一个运行请求和一个最新待处理项；不合作的提供者可以拖延新结果，
但不能发布旧文档修订或旧请求的数据。首次结果尚未返回时，词内编辑同样推进请求身份。

新候选按既有 Label 和实际编辑身份保留选中项；替换范围使用新文档快照的完整词范围。
尺寸按新候选重新测量，位置仍沿用既有锚点规则；没有隐藏／重新 Show 弹窗的步骤。
没有结果、词删空、越出原词、有效 Definition 改变、外部修改、一般选区 setter、
失焦／卸载、只读、预编辑／组合提交等情况继续取消旧会话。
合成输入、成对符号和结构化编辑沿用各自既有路径，不把所有模型变更都视为继续补全。

## 修改归属与重入

GOUI v0.7.0 的 Model.Change 不携带编辑来源；本次使用调用方的一次编辑许可绕过这一边界，
无需改动 GOUI 接口。本实现不使用跨整个回调作用域的保留开关：

- 词内输入生成私有的一次编辑许可，记录原 operationState、会话／提供者／请求代次及精确编辑。
- Model.Apply 前作废旧请求、将旧行禁用。许可只认可预期的下一修订和单项精确编辑。
- 变更处理在任何选区／变更回调前消费许可；本视图更新词范围与 pending 身份。
  其他共享视图没有许可，仍关闭自己的会话。
- 后续选择更新显式传递同一个会话；应用回调改变文档、语言、选区或提供者时不能继承许可。
- Word 是应用可配置的回调，查询前后校验上下文；回调替换文档后旧输入不得写入新文档。
- 实际编辑仍使用本视图原有 EditSource 与历史选区元数据，不改变撤销分组。

继续沿用既有 Monaco/Scintilla 的会话与呈现分离取舍。本次复核
[Scintilla 5 自动补全](https://www.scintilla.org/ScintillaDoc.html#Autocompletion)
（页面标示 2026-10-01）：输入匹配、当前项选择和取消是不同操作。
采用继续会话与取消的区分；不引入其字符串消息协议，也不新增 Provider 的过滤回调。
