# SourceView 测试与首版验收

> 状态：测试组织与验收规格。实际运行的命令、结果及缺口见 [实现记录](Plan.md)，不从本矩阵推定所有场景均已通过。
> 测试分类遵循 [AGENTS.md](../AGENTS.md)，具体切片见 [Plan](Plan.md)。

## 1. 测试落位与执行

- 语言扫描、行索引、失效传播、编辑计划、搜索及不可变配色放所属包 `*_test.go`。
- 不依赖桌面的真实 typography/离屏验证可放包内，仍遵守原生库、平台及线程亲和。
- 真实窗口、事件循环、系统剪贴板和 IME 验证放 `tests/window/<领域>/<主题>/`，
  为显式启动的 main 程序，不通过普通 go test 自动打开。
- 固定原文/期望放 `testdata/`；性能文本按种子生成，不提交数十 MiB 的重复样本。
- 预期包含 token byte 范围、分类、必要的行末模式、选区、修订与原生资源释放次数；
  不能只截图或比较两条共享同一错误算法的结果。

基础命令：

```bash
go test ./...
go test -race ./internal/... ./language/... ./scheme/...
GOWORK=off go test ./...
```

后续按实际包路径补充 bench/fuzz 与目标平台编译；GOWORK=off 的结果必须使用可解析的
GOUI 依赖版本，不以本地工作区成功代替。纯文档阶段以上命令不适用。

### 根包测试的职责与共享辅助设施

根包测试保留 `package sourceview`，直接验证已有私有状态，不为测试新增导出接口。
按实际职责归并用例，测试函数名和原有断言保持稳定：

| 文件 | 覆盖范围 |
| --- | --- |
| `sourceview_test.go` | 文档与视图隔离、通知重入及配置 |
| `commands_test.go` | 编辑命令、历史、自定义编辑规则、剪贴板与异步取消 |
| `input_test.go` | 指针与导航计算、预编辑生命周期、平台快捷键匹配及菜单命令 |
| `search_test.go` | 原始匹配与 cluster 选区、搜索范围、替换及高亮显隐 |
| `controls_test.go` | FindBar/GoToBar 生命周期、定位、配色与多语言 |
| `layout_cache_test.go`、`layout_cache_native_test.go` | 最近宽度、编辑和历史复用、资源隔离、失效、着色与光栅结果 |
| `layout_colors_test.go` | token、语言与选区前景及着色重入 |
| `layout_native_test.go` | 原生长行、初始高度估计、度量快照、上下文边界及补全省略 |
| `layout_test.go` | 可见行映射、滚动定位、帧间调度、分析计时器与工作集保护 |
| `paint_test.go` | 装饰几何和叠加顺序、可视区裁剪、只读语义快照 |
| `completion_test.go`、`completion_list_test.go` | 补全会话、提供器与列表的行为、失效及资源契约 |
| `folding_test.go`、`assistance_test.go` | 折叠与范围映射；缩进、配对、标签及标记语言联动 |
| `styles_test.go` | 主题注册、样式作用域及变化通知 |

共享辅助设施集中在 `test_helpers_test.go`，包含纯文档观察器 `observe`、输入法复位替身、
确定性排版、JSON 着色样本、通用绘制记录器及原生调用计数、度量副本和光栅范围辅助。
这些夹具不自动建立桌面会话，不通过全局可变对象共享视图或原生资源，
模拟排版和绘制记录也不能代替真实后端验证。

`native_helpers_{linux,windows,darwin}_test.go` 仅保留各平台 Context 工厂，
借文件名参与平台选择；不能为减少文件而引入跨平台运行时分支或混合原生依赖。
各原生用例仍负责实际执行 goroutine 的锁线程和资源销毁。

只在某一领域使用的夹具、故障注入和断言辅助函数留在该领域，
不为每个辅助类型或回归场景新增文件，也不建立额外测试框架。

`layout_experiment_test.go` 集中维护尚未接入控件的有界分段测量与上下文实验。
这些用例继续参与默认 `go test`，保留成功样本、明确反例及基准，
不能据此推断 SourceView 已启用该优化，或有限上下文可替代任意完整 Unicode 段落。
实验范围与当前局限见 [长段落实施记录](PlanIncrementalTextLayout.md)。

内部包同样按领域归并：`internal/editor/editor_test.go` 验证编辑计划、行和移动，
`search_test.go` 验证字面量、计数和正则；`internal/highlight/engine_test.go` 验证引擎、
行元数据和上下文，`scanner_test.go` 保留扫描适配器及各语言回归样本。
`language/language_test.go` 集中内置语言、Markdown 与折叠规则；
`language/definition_test.go` 保持 `package language_test`，继续从外部验证公开契约。

窗口验证保留现有入口路径；`tests/window/editor` 是基础集成程序，
各子目录是专题场景，`tests/window/experience` 是跨功能交互验证。
`go test ./...` 编译这些入口但不会执行其窗口场景，窗口验收必须单独启动并记录。

## 2. 必需的独立断言

| 领域 | 核心断言 |
| --- | --- |
| 行元数据 | 行数、每行长度、LF、byte->line 与简单字符串参考一致；稳定 LineID 只在确实未修改后缀保留 |
| token | 范围合法、rune 边界、有序、不重叠；片段拼接与手写小样本预期一致 |
| 增量 | 局部结果等于全量重算，但还需手写语言样本作为独立语义预期；证明已收敛后不会扫到 EOF |
| 历史 | 一个代码命令一次撤销；文本、修订、通知数量及前后双向选区准确 |
| 重入 | N 的通知不会用 N+1 文本布局；回调换文档/卸载不应用旧选区或旧分析 |
| 资源 | 原生 layout 创建/销毁匹配；卸载后 Model/Root/Timer 无视图回调，重挂载可恢复 |
| 搜索 | 全局 byte 范围、跨块/跨行、方向环绕、simple folding、WholeWord 和替换批次准确 |
| 快照 | VisibleText 恰好等于 VisibleRange 的模型切片，长度上限和 UTF-8 边界正确，preedit 独立 |

随机编辑测试使用固定 seed 和小规模朴素字符串参考，保存最小复现输入。
例如随机插入删除 LF、多字节字符、引号和注释标记后，检查行索引及分析状态。
正确性覆盖后再用 Go fuzz 发现边界，不以 fuzz 替代固定回归。

## 3. 三种语言样本

| JSON | XML | HTML |
| --- | --- | --- |
| 所有值类型、空结构、嵌套与属性名分行 | Unicode 名称、命名空间样式名称、双/单引号属性跨行 | 大小写标签、布尔属性、未引号值、跨行属性 |
| 转义引号、反斜杠、Unicode escape 的片段边界 | Entity、数字引用、Comment、CDATA、PI 与 Doctype | Entity、注释/DOCTYPE、style/title/textarea/plaintext |
| 01、1e+、非法转义、未闭合字符串后恢复 | 引号中的 > 与内部子集中的 ]/>，未闭合状态恢复 | script data / escaped / double-escaped 的结束边界 |
| JSONC 不偷偷当标准 JSON；深嵌套预算降级 | 不加载实体、不要求文档完整或 DTD 可用 | </scriptx> 不终结；JS 字符串不改写外层 HTML 规则 |

每种语言至少包含：
全文装载、逐字键入、选区替换、跨行删除、粘贴、Undo/Redo、语言切换，
以及分隔符恰跨 16 KiB 工作片段的情况。
在较后位置另造独立 dirty 区间，确认前段收敛不会跳过它。

先直接断言内置 Kind 和行末模式，再验证 Scheme 映射。
不使用平台像素差异来解释错误 token，也不为“高亮看起来正常”省略 byte 断言。

## 4. 纯逻辑编辑场景

- 正反选区、多行末端恰在下一行首、空末行，缩进/反缩进的一次提交和撤销。
- 粘贴和 IME 提交是独立历史项；普通打字可合并，导航、换源和批次会断开。
- G1 的校验失败完全无副作用，Change.Edits 顺序能从旧文还原新文。
- 外部编辑按粘性策略映射其他视图；Undo/Redo 仅恢复发起操作视图的历史选区。
- 查询跨读取片段及 LF，替换文本包含原查询不循环；超操作预算在提交前拒绝。
- 查询只匹配 Cluster 的部分 rune 时，视觉扩展不扩大 ReplaceCurrent 的源修改范围。
- 只读下所有修改入口不改内容/历史；外部 Model 编辑仍正常更新展示。
- 剪贴板同步回调、迟到回调、失败、空文本和无文本分别断言；Cut 写失败不删除。
- 销毁/换文档/禁用/只读与新的 pending request 都能阻止旧粘贴。

## 5. 原生排版与窗口主题

按需创建下列独立主题程序，每个入口附环境、步骤与逐项预期：

| 主题 | 必须观察和可计算的结果 |
| --- | --- |
| editing | 鼠标拖选、键盘 Cluster 导航、双向文本、剪切复制粘贴、Undo/Redo 与只读 |
| ime | CJK、组合字符/emoji 的预编辑、提交、取消、候选框随滚动/缩放移动 |
| gutter | 横向滚动时行号固定，9->10、99->100 宽度变化，折行续行无重复号 |
| reveal | caret 不落在行号后；软折行/行高更新后定位；视口锚点与主动导航不互相拉扯 |
| theme | 亮暗与非焦点选区、当前行/搜索/选区叠加、token 消失后无旧色 |
| typography | G2 的重复站点、字体/fallback、RTL、折行、DIP 与真实 DPI |
| lifecycle | 同 Model 多视图、窗口间重新挂载、关闭/重建时无旧帧与原生资源残留 |
| languages | 三种语言边编辑边着色，不完整输入可继续编辑；冷定位未知区域先 Plain 再正确恢复 |

人工输入与 AI Computer Use 均走真实桌面输入。模拟逻辑输入仍需正常 DispatchEvent 路径。
剪贴板修改由测试页面上的明确操作触发，程序注释写明副作用。
不以 DevServer 代替既定真实窗口验收。

平台矩阵以 GOUI 实际支持后端为准，分别记录 Linux、Windows、macOS 的系统、
后端、字体和 DPI。应用内 1x/2x 缩放不能冒充真实混合 DPI。
首轮至少验证一个原生桌面与另两目标编译，发布前补齐三端关键输入/Tab/剪贴板；
未运行部分一直标未验收。

## 6. 规模与初始性能目标

以下是开发目标及测试 profile，不是已经实现的性能或对所有硬件的保证。
先在固定环境建立基线，再按同一资源、后端和测量范围作前后对照。
当前阶段按用户要求优先验证中大文件功能，以下延迟/资源目标保留为后续专项，
不作为本轮功能通过阈值。当前样本、操作、问题修正和回归结果见 [中大文件验证](PlanLargeFiles.md)。

| profile | 规模 | 关注点 |
| --- | --- | --- |
| 正常 | 1 MiB、约 10,000 行，单行通常 40..200 byte | 输入、滚动、初次可交互、高亮收敛 |
| 较大 | 10 MiB、约 100,000 行，单行不超过 16 KiB | 索引、局部失效、缓存上限与尾部冷定位 |
| 超长行 | 16 KiB、64 KiB、1 MiB 单行，含 Tab/Unicode | 单次 native shaping、caret/命中正确性、峰值内存 |
| 压力 | 100,000 次命中、深嵌套、密集 token、大选区 | 操作预算、取消/降级、不复制无关全文、不泄漏 |

固定参考环境上的初始目标：

- 常规单字符命令的模型修改、索引失效及命令返回 P95 目标不超过 2 ms，
  排版与实际帧另测，不能只报快的部分。
- GUI 高亮单文档驱动约 2 ms、同 Root 总预算 4 ms、片段 16 KiB，测量实际最大超额；
  预算不覆盖不可中断的原生 shaping 或单次模型提交。
- 正常 profile 事件分发到对应绘制完成的 P95 目标不超过 33 ms；
  这是应用侧帧指标，不能当屏幕合成的 end-to-end 延迟。
- 普通不改变后续语法状态的局部编辑，应只重扫受影响行/片段和必要收敛行；
  非首行小编辑不能在每次键入自动读取全文。
- 用引用数/缓存计数证明只缓存可见工作集，不为整份文件创建 native layouts。
- 反复挂载/卸载和语言/主题切换后，句柄数量与缓存占用稳定，不随次数线性增长。

记录首屏文本可见、首次可输入、全量分析完成为三个时间点，冷启动不能只测最后一个。
超长行的正确性要求不变，延迟不套用常规 33 ms 目标；保留实测与限制。
目标未达时定位模型、分析、排版、栅格或宿主调度，再调整设计，
不得通过跳过输入、截断行或临时放宽断言掩盖。

## 8. 编辑体验窗口

运行 `go run ./tests/window/experience`，环境与复位规则见入口注释。
程序逐帧检查双击/三击、字符后半部命中、显式局部选区前景、右键保留、菜单键盘和鼠标执行，
以及 JSON/HTML 候选的键盘/鼠标确认、自动触发、只读/卸载取消、提供者重入、
配对插入/跳过/包裹/删除/换行缩进及单次撤销。提前关窗按未完成退出，不能计为通过。

原生字体的字符区域由实际 MeasureMetrics 建立，局部选区位图与同后端独立排版比较。
Rasterize(1, region, nil) 返回调用方拥有的预乘 RGBA；比较相同显式区域的尺寸、stride
和全部像素，允许误差为 0。显式复用 buf 时先保存仍需比较的旧结果；
不使用跨平台字体金图。这验证文字前景范围，不代替合成后的桌面截图或背景视觉检查。
菜单新开后的行实现等到下一帧再断言；输入只用 Window/Popover.DispatchEvent 和 CommitText，
不通过私有状态或菜单 Action 回调执行模拟操作。普通测试不碰系统剪贴板。

单元回归覆盖词拖选方向、词尾命中、菜单权限/历史、配对及标记映射、字符串/注释状态、
补全替换词后缀、Unicode 文档词、候选去重与窗口边界、关闭回调切文档时不提交旧范围。
具体平台结果和发布限制见 [编辑体验验收](PlanEditorExperience.md)。

## 12. 编辑快捷键与内置查找栏

`go run ./tests/window/editor/shortcuts` 自动检查插入行、缩进、整行扩选、词操作、括号及搜索导航，
并验证 Unicode、撤销、共享视图、只读消费和未绑定组合键的传播。解除绑定的编辑器不得拦截应用的查找入口。

`go run ./tests/window/editor/find` 在真实声明式树中检查查找栏开关、查询种子、选项、计数、
替换/撤销、焦点，以及重建、多视图隔离、移除和重挂载、取消绑定、未完成计数失效、外部回调与宿主销毁。
两者的输入均经正常 Window.DispatchEvent / CommitText；源码入口说明启动环境和逐项预期。
固定文本及分块计数与独立 strings.Count 比较；重叠匹配采用明确的原文范围预期。

## 13. 查找浮层外观与隔离

XMODIFIERS=@im=none GOUI_PLAT_PAINTER=software go run ./tests/window/editor/find_appearance
