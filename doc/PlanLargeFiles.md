## 范围与判定

程序在 `tests/window/editor/largefiles`。使用原创生成的 JSON/XML/HTML 常规多行文件，
固定长度内容含中文、组合字符和 ZWJ emoji；首部、中部、尾部有独立标记，查询词只出现三次。
实际样本写到仓库外临时目录，从磁盘 ReadFile 后 SetText，最后删除；不提交大型重复文件。
生成器的标准库解析、计数及标记位置测试不依赖桌面。

窗口输入经正常 Window.DispatchEvent / CommitText。自动补全关闭以固定操作序列；
配置 setter 和文件加载只准备场景，不使用 DevServer、私有动作或导出的测试状态。
原生排版在主事件循环线程创建、调用和释放。

每种配置执行 53 个步骤，主要断言如下：

- 加载的完整字节内容、逻辑行数及初始历史；加载后不等待高亮直接输入并撤销。
- 首/中/尾定位和可见原文，原生 property/tag 前景最终使用语法色；Unicode 输入、删除、撤销/重做。
- 文档首尾、PageUp/PageDown，行移动/复制/删除，100 行缩进及一次撤销。
- 查找栏计数、三处匹配的正反导航、当前替换、全部替换和历史原子性。
- 只读输入与历史限制，共享视图的内容、选区位置映射及撤销。
- 新视图冷定位、卸载重挂后的定位，折行前后的顶部逻辑行锚点及主题切换。

内容校验按原文件切片及明确给出的插入/删除片段独立构造预期，逐段比较整份模型，
不调用生产编辑计划或位置映射计算预期。文字颜色通过公开 Typography 包装观察原生前景调用；
截图仅作观察，不作为字体或像素金图。可见原文及范围另与模型精确比较。

可见性断言失败不修改模型，因此记录后继续独立的后续场景；内容或其他断言失败立即中止。
只要存在失败，程序最终仍返回非零，不把“程序跑完”计为通过。
每个等待步骤最多 120 秒，外部进程另有超时；耗时日志含定时器间隔和全文校验，不能作为输入延迟。

## Linux 实测

环境为 Ubuntu 22.04.5 / amd64、Go 1.25.8、Pango，临时 TigerVNC / Xfwm4，
compositor off、XMODIFIERS=@im=none；实际 Painter 和缩放由绘制探针确认。

| 语言 / 约 MiB | 实际字节 | 逻辑行数 | 配置 |

| JSON / 1 | 1,048,563 | 5,143 | Software 1x 对照 |
| JSON / 10 | 10,485,603 | 51,403 | Software 1x |
| XML / 10 | 10,485,636 | 48,103 | Software 1x、2x |
| HTML / 10 | 10,485,574 | 55,191 | Software 1x、OpenGL 1x |

| HTML / 50 | 52,428,644 | 275,944 | Software 1x |

十组配置均完整执行 53 个步骤：每组 50 个步骤通过，3 个可见性断言失败，进程退出码为 1。
失败分别为新共享视图尾部定位、该视图在共享编辑后的同一可见性检查，以及主视图重挂载后的
中部定位。整份内容、加载后不等待高亮的输入、历史、搜索替换、折行与主题顶部锚点等检查通过。
这代表多个场景复现同一类定位问题，不是 30 个独立缺陷，也不代表整组窗口验收通过。

运行方式，例如：

```bash
XMODIFIERS=@im=none GOUI_PLAT_PAINTER=software GOUI_PLAT_SCALE=1 \
  go run ./tests/window/editor/largefiles -language json -mib 50
```

`-data-dir` 可指定仓库外现有临时目录，`-capture-dir` 可在现有临时目录输出首/中/尾截图。
临时桌面和窗口退出时清理，没有修改用户桌面、剪贴板或系统设置。

## 已复现的功能问题

冷定位存在可见性问题：新挂载的第二视图请求尾部定位，以及卸载重挂后请求中部定位，
Selection 的 byte 位置正确，但目标行没有进入可见区域。
共享文档随后编辑时，第二视图的选区映射正确，原有的可见性偏差仍存在。

例如 50 MiB JSON：第二视图 caret 为 52,428,438，可见原文结束在 52,428,001；
重挂载后的中部 caret 为 26,214,234，可见范围结束在 26,213,389。
这不是丢失内容或选区坐标映射错误；相同问题在 1 MiB 对照样本也可复现。

当前证实的是外部可观察结果。源码提示需要检查 SourceView 的高度估计更新、
待完成 caret reveal 与顶部锚点恢复的优先顺序，以及与 ScrollView 的协作；根因和修正尚未验收。
下一步先为这些触发条件设计最小功能修正，不以更换文本模型或资源优化代替定位修复。

草稿曾要求折行后 caret 始终可见；复核 [布局契约](DesignLayout.md#3-逻辑行显示行和高度) 后，
最终改为核对顶部逻辑行锚点、选区及完整内容。折行及主题切换按该契约验证，
不将早期草稿的错误预期计为产品缺陷；冷定位的原可见性断言保留。

## 冷定位修正（2026-10-18）

修正前基线为 SourceView `84779c1`，GOUI 仍为上述 `903daf8`。
修正与回归用例提交为 `4342949`。本轮生产修改仅在 SourceView；
没有调整大型样本、等待条件或原来的可见性断言。

源码、固定度量回归与原生窗口复测确认了两处时序问题：

- 原先只按估计高度发送一次 caret 矩形；目标上方行随后获得实际高度，目标会移出视口。
- 重挂载后 SourceView 保留旧偏移，但宿主已经归零；`Arrange` 的临时偏移不能确认定位完成。

修正保留当前逻辑定位请求，先测量目标附近约一个估计视口，再发送更新后的矩形；
可见范围最多重查一次，后续变化经正常布局处理。只在宿主交付的偏移下确认目标可见，
然后捕获顶部锚点。新选区、文档变化及卸载取消旧请求，回调后核对请求身份与生命周期。
没有新增滚动宿主、定时补偿、公共 API 或文本存储机制。参考与取舍见
[布局设计](DesignLayout.md#3-逻辑行显示行和高度)。

`layout_reveal_test.go` 用 20 DIP 基准行高与 32 DIP 实际正文行高建立独立预期，
通过真实的 GOUI ScrollView 布局验证冷定位、重挂载前后的不同偏移、零分配后的首次布局、
过短视口、新选择/文档替换/模型变化/卸载取消、滚动回调重入及完成后自由滚动；
同时核对 native mock 的创建/销毁平衡。旧版冷定位用例在连续八次布局后仍失败，
caret Y=116、高=32，视口高=100。只增加待完成请求的中间修正仍在原生 XML 场景失败，
因此最终同时补齐目标附近测量；没有用延长等待或后续编辑触发的恢复代替首次定位通过。

样本临时目录在完成后为空；临时窗口和桌面退出，没有修改用户桌面、剪贴板或系统设置。
