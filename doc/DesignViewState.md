# 视图状态恢复设计

状态：2026-11-10 复核提案，尚未实现。近期在补全呈现之后推进，不等待保存点依赖。
不依赖保存点新增 API，不修改 typography，不保存原生布局。

## 范围与接口

用于进程内标签切换、视图销毁后重建、同一 Document 的多个独立视图。
保存有方向的选区、滚动文本锚点、横向位置和折叠意图；不保存正文、历史、主题/字体、
配置、补全/预编辑/查找面板或原生资源。文件持久化和标签管理仍归应用。
影子建议也属于临时视图状态，不保存建议文字或额外高度；捕获位于建议虚拟区域的视口时，
回退到其真实插入点，并去掉虚拟区域的垂直 inset，避免恢复时产生没有建议的空白。

```go
func (v *SourceView) CaptureViewState() (*ViewState, error)
func (v *SourceView) RestoreViewState(state *ViewState) error
```

ViewState 字段私有且不可变，复制折叠数据，不持有 Widget/Document/Model 引用，无需 Destroy。
第一批只支持同 Document、同 Revision；其他视图编辑后旧状态明确拒绝，不按过期偏移猜位置。
需要跨后台编辑保留位置时，应用可保留活视图使用既有映射。跨修订和跨进程恢复后续单独设计，
不提供 JSON 序列化承诺。ui 增加别名，通过正常控件引用调用，不增加每次协调重置滚动的属性。

Capture 要求挂载且视图已观察到当前模型修订，否则 ErrNotMounted/ErrOperationChanged。
不改变选区、焦点、历史或折叠，不强制排版。IME 期间只捕获提交文本的选区和锚点，
不提交/取消输入法，不保存投影内容。

Restore 校验 nil/无效状态、挂载、Document 身份和 Revision；失败不改变视图或旧恢复任务。
接受后取消补全、影子建议、待执行编辑/粘贴与预编辑，回调后重新核验；不强行提交预编辑或自动获取焦点。
只读视图可以恢复。nil 返回表示接收意图，不表示测量已完成；每视图至多一个恢复意图。
不产生正文修订、撤销项或 modified 变化，保留反向选区，不逐次调用带 reveal 的 API 来回滚动。

## 锚点与延迟几何

现有 layout.go 的 viewportAnchor 已保存 offset/inset/x，pendingAnchor 在后续布局解析位置。
Capture 复用已测量的可见几何，Restore 复用该调度通路，并补齐折行边界的亲和性。
快照内部保存：

- 顶部视觉行的提交文本 UTF-8 位置及前/后行亲和性。
- 顶部行被裁掉的垂直距离和横向偏移，单位 DIP。
- Anchor/Caret 及光标亲和性，不保存平台 caret 或布局。

按当前宽度、字体、缩放和换行方式重新找到锚点所在视觉行，inset 钳制到新行高，
横向位置钳制到当前滚动范围。同尺寸尽量恢复原视口，尺寸变化只保证锚点附近稳定。
不用旧 Y 或估算总高度代替文本定位，也不保证不同字体产生相同截图。

尚无精确几何时使用当前有效的待定位文本锚点；无有效锚点则回退估算顶部逻辑行起点，inset=0。
已挂载尚未布局时使用选区 caret，空文档为 0。此为明确近似，不启动同步原生测量等待结果。
恢复优先调度锚点附近有限排版，复用分片/缓存与事件循环预算，其余内容延后。
几何就绪后校正滚动；保留保存视口优先，不把屏外 caret 强制滚入屏内。

## 折叠意图

只复制已折叠区域的正文端点，不复制全部候选、隐藏行索引或分析状态。
同修订但语言定义改变时恢复选区/视口并舍弃旧折叠；不切回旧语言，不开启已关闭的折叠。
内部记录 Document 的语言代次用于判断，不长期持有语言对象。
同语言下只匹配起止端点完全一致的候选，不按标题或候选序号猜测。
恢复替换当前折叠意图：未记录的区域展开，不存在的区域忽略；隐藏选区端点的区域展开。

分析未完成时保留有界集合，沿用 foldIntake 分批匹配；完整结果到达后应用一次并清理，
不在后续分析中反复覆盖用户操作。候选长期未返回时数据仍有界，可被用户操作或卸载取消。
首批上限为 4096 个已折叠区域，超限 Capture 返回 ErrOperationLimit，不静默截断。
捕获应按已折叠集合枚举，不为少量折叠扫描全部候选；在既有 fold 状态维护一致索引，
覆盖编辑映射、禁用、结果替换等路径，不维护第二套分析结果。
匹配分批执行，不能同步 FoldAll 再逐一折叠来掩盖 O(F) 工作。

## 生命周期、资源与语义

恢复意图包含文档、修订、挂载身份及内部代次；新恢复替换旧意图。
输入、鼠标定位、滚轮/滚动条、显式选区/导航/折叠操作取消旧意图，用户操作优先。
恢复自身的滚动通知不能误判为用户取消，应区分调用来源，不能忽略所有滚动事件。
改尺寸使几何失效但继续定位；换文档、卸载或销毁取消并释放状态。

内部先设置一致的选区、折叠及定位意图，再发已有变化通知，回调后核验代次。
外部回调启动新恢复或换文档时旧任务不继续操作。无需再加 ViewStateChanged 信号。
语义快照反映实际选区、边界和折叠，不提前声称未测量的目标已显示，不给纯装饰添加动作。
快照内存 O(C)，C 是有界已折叠数量；没有全文副本。原生对象仍归现有布局缓存，不跨视图共享。

## 实施与验证

预计 view_state.go 集中快照/恢复协调，调整 layout.go 锚点、folding.go 折叠索引和接收、
输入/滚动取消入口及 ui/types.go，不为几十行拆新包。先选区/锚点，再折叠意图，各自带测试提交。
逻辑测试覆盖身份/过期拒绝、快照隔离、预算、候选精确匹配、重入、取消及双视图隔离。
独立 X11 会话通过正常事件验证：

- 反向选区、屏外 caret、折叠后切标签及销毁重建同文档视图。
- 改宽高/字体、100%/150%，超长单行自动换行中段、部分视觉行与双向文本。
- 慢折叠/无几何时恢复后立即滚动或输入，迟到结果不抢回位置。
- 10 万候选但少量折叠、4096 折叠及超限，约 10 MiB 文本。
  测量实际切换到首屏及事件循环间隔，不只测 Restore 返回。
- 两视图的滚动/折叠互不污染；另一视图编辑后旧快照明确失败。

执行 go test ./...、GOWORK=off go test ./...，按风险补 race 和 Windows/macOS 编译；
桌面检查 Basic/Modern、亮暗主题并记录原生平台缺口。当前不要求 GOUI 新接口；若发现
通用缺口先记录，不绕过公开契约。

## 参考与取舍

2026-11-10 复核公开契约，未做参考编辑器桌面或性能实测：

- [Monaco ICodeEditorViewState](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.ICodeEditorViewState.html)
  分开光标、视口与贡献状态；采用正文/视图分离，不建任意贡献字典。
- [Monaco IViewState](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.IViewState.html)
  在线 API 未固定发行号，包含 firstPosition、firstPositionDeltaTop、scrollLeft。
  采用文本锚点加局部偏移，不承诺其完整可序列化能力。
- [Scintilla 滚动](https://www.scintilla.org/ScintillaDoc.html#ScrollingAndAutomaticScrolling)
  提供可见行与横向位置控制；本项目延迟自动换行不能只保存旧行号或像素位置。
- [GTK4 TextView.scroll_to_mark](https://docs.gtk.org/gtk4/method.TextView.scroll_to_mark.html)
  是 GtkSourceView 通用文本基础的定位参考，不等于完整视图快照契约。
  具体恢复顺序、预算和过期拒绝均是本项目取舍，复用上层锚点，不扩充 typography。
